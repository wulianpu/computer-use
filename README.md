# computer-use

> `computer-use` is an independent Agent Plugins 1.0.0 distribution of Cua
> Driver. It mechanically projects the official Cua Driver Agent Skill into
> a conforming Agent Skill and directly exposes the official
> `cua-driver mcp` runtime. It does not implement Computer Use behavior.

```text
All Computer Use behavior and operating guidance originate from Cua.
computer-use owns only standards packaging, deterministic projection,
verification, and qualification.
```

```text
                    trycua/cua
                        │
            ┌───────────┴───────────┐
            │                       │
     Official Cua Skill      Official Cua Driver
            │                       │
            │ deterministic         │
            │ projection            │
            ▼                       ▼
 skills/cua-driver/*          cua-driver mcp   (mcp.json, stdio)
            │                       │
            └───────────┬───────────┘
                        │
                   computer-use
                        │
                 Agent Plugins 1.0
                        │
                        ▼
                 Agent Plugin Host
```

`computer-use` is not located between the agent and Cua; it only stands
between Cua and the Agent Host as standards packaging.

## Production surface

| Artifact | What it is |
| --- | --- |
| `plugin.json` | computer-use Agent Plugins packaging |
| `mcp.json` | generated declaration of the **official** Cua MCP entrypoint (`cua-driver mcp`, stdio) |
| `skills/cua-driver/*` | **projected** official Cua Skill — generated by `scripts/project_cua_skill.py`, never hand-edited |

Production code authored by this project: **0**. There is no self-written
MCP server, no Computer Use runtime, no wrapper, and no independently
authored operating guidance.

## Skill projection model

The raw upstream skill pack (pinned by `upstream/cua.lock.json` to
repository + version + tag + immutable commit + per-file sha256) lives in
`upstream/source/cua-driver/`. `scripts/project_cua_skill.py` projects it
into `skills/cua-driver/` with the minimal, explicitly registered transform
set in `upstream/projection.json`:

- `normalize-agent-skills-frontmatter` — standard Agent Skills frontmatter.
  The upstream `name` is preserved verbatim; the upstream `description` is
  transport-normalized only ("via the cua-driver CLI (default) or MCP
  server" → "via the Cua Driver MCP server") with its original SHA-256
  retained in projected metadata (`upstream-description-sha256`)
- `insert-generated-notice` — provenance comment
- `prefer-agent-plugin-mcp-transport` — fail-closed transport
  normalization: the description phrase above, plus the upstream
  CLI-default "GUI transport defaults" block (which mandates CLI-first)
  is replaced byte-exactly by the Agent Plugin MCP transport contract,
  plus a boundary note scoping the shell/management section to hosts that
  really provide a shell
- `exclude-host-specific-mcp-setup-guidance` — the Claude Code
  compatibility/setup subsection (host-specific install guidance, e.g.
  `cua-driver mcp-config --client claude`) is not Computer Use behavior
  and is removed from the host-neutral plugin
- `remove-plugin-side-native-installer-execution` — the Windows
  `irm … | iex` one-liner becomes "refer the user to the official guide and
  stop"; the plugin never installs native executables
- `exclude-upstream-pack-readme` — the pack-level README is not projected

Everything else is byte-exact. Transforms fail closed: if an expected
upstream block changes, projection fails and demands manual review.
`scripts/verify_projection.py` re-proves offline that the committed skill
tree equals the deterministic projection (regeneration comparison), and
`upstream/projection-report.json` summarizes what changed for reviewers.
The long-term goal (tracked via trycua/cua#3387) is an upstream portable
skill with **zero transforms**.

## Requirements

The plugin does **not** bundle Cua. The host environment must provide a
`cua-driver` executable on `PATH` (qualified against Cua Driver **0.24.0**).
If the executable is missing, the plugin is simply unavailable — it never
installs or updates Cua at runtime. Installing Cua is user/host environment
setup: <https://cua.ai/docs/how-to-guides/driver/install>.

## Development tools

| Tool | Purpose |
| --- | --- |
| `scripts/sync_cua.py` | Download and pin the official skill pack at an exact tag/commit (fail-closed on shape drift). Writes `upstream/source/` + lock only. |
| `scripts/project_cua_skill.py` | Deterministically project the raw source into `skills/cua-driver/`; writes `projection.json` + `projection-report.json`. |
| `scripts/verify_upstream.py` | Offline: raw source hashes vs lock, license, notices. |
| `scripts/verify_projection.py` | Offline: skill tree == regeneration, projection.json consistency, receipt validity (projection digest bound). |
| `scripts/validate_plugin.py` | Official pinned Agent Plugins schemas + project policy (identity, deterministic mcp.json template, projected-skill conformance, no local runtime). |
| `scripts/mcp_client.py` | Minimal MCP stdio client — development-only qualification harness. |
| `scripts/mcp_probe.py` | Level 2: real `cua-driver mcp` handshake, `tools/list`, required tool subset, optional contract snapshot. |
| `scripts/e2e_calculator.py` | Level 3: Calculator `6 × 7 = 42` qualification — semantic-only, ownership-proven, dry-run unless `--yes`. |

```bash
pip install -e ".[dev]"

python scripts/sync_cua.py --tag cua-driver-rs-v0.24.0
python scripts/project_cua_skill.py
python scripts/verify_upstream.py
python scripts/verify_projection.py
python scripts/validate_plugin.py
python -m pytest -v

# Requires a real cua-driver on PATH (Level 2+)
python scripts/mcp_probe.py --snapshot

# Requires a real interactive desktop (Level 3); dry run by default
python scripts/e2e_calculator.py --yes
```

## Validation levels

| Level | Name | Needs | Covers |
| --- | --- | --- | --- |
| 1 | Portable | nothing | official-schema + policy validation, upstream hashes, projection verification, unit + fake-MCP tests (CI) |
| 2 | Cua MCP contract | real `cua-driver` | version, handshake, tools/list, required tool subset |
| 3 | Desktop qualification | real OS + GUI + Cua | structured/image state, semantic actions with asserted element tokens, exact result verification, ownership-proven cleanup |
| 4 | Supported | concrete version + platform receipts in `upstream/compatibility.json` | support matrix |

Qualification receipts bind `version + upstreamCommit + skillSource +
projectionMode + projectionDigest + pluginCommit + driver artifact sha256`;
any change invalidates them.

## Verified support

v0.1.0 has been project-qualified on:

- Windows 11 (build 26200)
- x86_64, interactive desktop
- primary display DPI 100%
- Cua Driver 0.24.0 (official release binary, sha256-verified)
- L2 MCP contract + L3 Calculator semantic E2E (`6 × 7 = 42`)

Other Cua-supported platforms and environments (other Windows builds and
DPI scales, macOS, Linux, multi-monitor, other applications) have **not**
been independently qualified by computer-use — Cua's own capability
coverage is broader than what these receipts certify. Actual verified
support is defined exclusively by `upstream/compatibility.json`.

## Ownership boundary

```text
Agent Plugins  → plugin package format
Agent Skills   → SKILL.md format
MCP            → agent ↔ server protocol
Cua            → Computer Use Runtime, MCP Server, tool contract, agent guidance
computer-use   → packaging, projection, upstream sync, verification, qualification
Agent Host     → installation, MCP lifecycle, authorization, approval
Operating OS   → the final desktop security boundary
```

> **If a piece of production Computer Use behavior is authored in
> `computer-use` instead of coming from Cua, the architecture has probably
> drifted.**

## Security posture

- No default unrestricted permissions; authorization belongs to the Host,
  desktop security to the OS.
- No automatic Cua install/update, no runtime network access, no wrappers,
  no auto-executed installer guidance (projected out).
- UI content observed through Cua is untrusted data; no automatic replay
  of uncertain state-changing actions.
- No automatic screenshot persistence, no secret logging.
