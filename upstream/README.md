# upstream/

This directory separates two different questions:

## `cua.lock.json` — what we reference

The immutable source lock. It pins the exact upstream repository, version,
tag, commit, skill source path, and the sha256 of every mirrored skill file.
It is generated by `scripts/sync_cua.py` and consumed by
`scripts/verify_upstream.py`. Manual edits are forbidden.

## `compatibility.json` — what we actually verified

The live qualification record. It never changes automatically just because
Cua publishes a release. An environment may only be added to `verified`
after it passes Level 2 (MCP contract probe) and Level 3 (real desktop
qualification) on a real machine.

Suggested shape of a `verified` entry (record the concrete environment):

```json
{
  "version": "0.24.0",
  "platform": "windows",
  "environment": "Windows 11 24H2, x86_64, interactive desktop, DPI 100%",
  "levels": ["L2", "L3"],
  "date": "2026-09-08",
  "notes": "Calculator E2E 6x7=42 PASS; Chrome + Electron spot checks PASS"
}
```

Linux entries must name the display server / compositor (X11, GNOME
Wayland, KDE Wayland, Hyprland, …) — a blanket "Linux supported" record is
not accepted. macOS additionally needs the TCC/responsible-application
environment named. Entries whose `version` no longer equals the candidate
are dropped automatically by the next `sync_cua.py` run.
